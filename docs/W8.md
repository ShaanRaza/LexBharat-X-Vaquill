# W8: Orders and Schedules, scanned PDFs, statute links in judgments, feedback and usage stats

Everything here runs locally on port 3100 on free plans. Nothing is pushed. Keys, passwords and connection strings are never printed or committed.

**Method.** `scripts/supplement/schedules.mjs` finds every unit from the PDF's own layout (same pdf.js line reader as the sections, `pdf-text.mjs`): Orders by their centred "ORDER VII" headings, Rules by the same "N. Heading.—" start rule the sections use, Articles by the column positions of the two tables. `scripts/supplement/fill-schedules.mjs` checks every word of every unit against the PDF's own text (`pdftotext`, between the pages it spans; the looser `loose` mode only tolerates words the PDF itself glues or splits, like "subNinety") and writes one fill-in file per unit into `content/supplement/schedules/` (955 files, all passed: 0 failures). `npm run load:supplement` loads them into the existing supplement table (never touching open-india-law rows), embeds them with voyage-4 at 256 dimensions into `supplement_emb_256` and keeps the 900 MB stop line (main database 693 MB before, 694 MB after).

**Numbers.** `O39R1` = Order 39 Rule 1, `O39` = the Order itself (its title plus the list of its Rules' headings), `A137` = Article 137. Words for the screen come from `src/lib/acts/unitLabel.mjs` ("Order 39 Rule 1", "Article 137"); the UI, the chat prompt, the review text and the citation chips all use it.

**Lookups** (`src/lib/acts/searchQuery.mjs`, `src/lib/chat/lookups.mjs`): "Order 39 Rule 1 CPC", "O.7 R.11", "O 37 CPC", "Rule 11 of Order 7", "Order 39 Rules 1-2" (both rules), "Article 137 Limitation Act", "Art. 113 Limitation", "Art 36 stamp act". A bare "Article 21" is not a lookup (it is the Constitution, which we do not hold). In chat, "What is Order 7 Rule 11?" runs the lookup itself; meaning search finds units too (they are in `supplement_emb_256`), and Drafting and Review use the same retrieval.

**Act page.** The Limitation Act and the Stamp Act pages have a "Schedule as a table" link (`?section=schedule`): a table on desktop, one card per Article on phones. Stamp Articles carry the "Central rates; most States have their own" note.

## Part 1. Scanned PDFs, JPG and PNG in the Vault

- New `ocr` task in `src/config/ai-models.json` (Gemini document reading now; Claude later by changing the config or `AI_MODEL_OCR`). The AI layer now accepts files (PDF pages, images) on a message for Gemini, Anthropic and OpenAI-compatible endpoints.
- A PDF page with almost no text (fewer than 25 characters) is an image-only page. A mixed PDF keeps its text pages as they are and only the image-only pages are read. JPG and PNG uploads are one scan page.
- Reading goes in groups of 5 pages (`scanGroupPages`), one request per step, each page saved as it is read in `vault_scan_pages`, so an interrupted or busy document resumes where it stopped. Page numbers are kept (chat cites "page 3", review shows "Page 3").
- Where it shows: the Vault list and document page ("Read from scan — check the original", per page and for the whole file), chat sources ("· Read from scan — check the original"), review (notice at the top, "Read from scan" badge and page on each clause).
- Limits (config): 20 scanned pages per document (the rest are listed as "not read"), 5 scanned documents per browser per day (counted once per document, a deleted document does not give one back). Messages are shown as written in the Vault.
- If the model is busy, the document goes to "Waiting to read" (not "Can't read"), and the Vault page, or the next visit, picks it up again.
- Hindi/Devanagari is kept as printed (the prompt says never to translate).

## Part 2. Statute links in Supreme Court judgments

`src/lib/judgments/statuteLinks.mjs` (pure, tested) finds "Section 302 IPC", "ss. 302, 34 of the Indian Penal Code", "Indian Penal Code, s. 302", "Order XXXIX Rule 1", "Or. 7 r. 11", "Article 137 of the Limitation Act" in the opening text of a case; `src/lib/judgments/statuteResolve.ts` links a mention only when the Act is one of ours (`src/config/statute-acts.json`) and the section or unit exists in our data, or is known to be missing from the source data (then it links to that page). Anything else stays plain text. A "Laws referred to" list under the opening text groups them by Act. Existing extraction is untouched.

Rules that keep it from guessing: a number with no Act named next to it is never linked; "Order 39 Rule 1" with no mention of the CPC anywhere in the text is not linked; "Arbitration Act", "Limitation Act" and "Specific Relief Act" with no year are linked only for judgments decided after 1995 / 1963 (before that they meant older Acts); "Penal Code" is the IPC only when written with 1860; "Bankers' Books Evidence Act" is not the Evidence Act.

What is not linked: the **Constitution** (not in our data: only tiny State fragments) and the **Code of Criminal Procedure, 1973** (our data has only State-filed copies, no Central Act), so those appear in "Laws referred to" as plain text. The Indian Penal Code and the Indian Evidence Act are the repealed Central versions (we hold their full text), so they link to those.

## Part 3. Feedback and usage stats

- 👍/👎 under every chat answer, draft and review (`src/components/workspace/FeedbackBar.tsx`). A 👎 opens quick picks (Wrong law, Missing law, Wrong facts, Too vague, Other) and an optional comment; "Thanks" appears; the vote can be changed (one row per browser and item). Stored: item id, vote, picks, comment, model used, and a snapshot read by the server from its own copy (chat: question, answer, citation labels; draft/review: names only, never document text). The browser id is stored only as a hash.
- Per-day counters (`usage_daily`): visits per workspace page (once per browser per page per day), chats asked, drafts per template, reviews run, documents uploaded, scans read, limits hit, model-busy errors, average answer time. No IP address and no document text.
- Tables are in Supabase (not Neon), RLS on with no policies, from `scripts/w8/w8-schema.sql` (already run once).
- `/admin/insights`: protected by `ADMIN_PASSWORD` in `.env.local` (it must differ from `ACCESS_PASSWORD`, otherwise the page stays closed), behind the site password as well. Shows totals by day, visits by page, drafts by template, 👍/👎 per feature with the share of 👍, the list of 👎 with question, answer, citations and comment, and a CSV download.
- Vercel Web Analytics: package installed and `<Analytics />` added. **One toggle to switch on in Vercel:** project > Analytics tab > Enable.

**Tests** (`scripts/w8/feedback-test.mjs`, `feedback-test-more.mjs`; real server, real Supabase): 19 of 19 passed: answer ends with its message id; one question counted once with its answer time; vote saved; vote changed to 👎 with picks (an unknown pick is dropped) and a comment, returned on the next load; one row per browser and item; snapshot holds question, answer, citations; back to 👍 clears picks and comment; another browser cannot vote on my answer; bad payloads refused; three visits count once, unknown pages ignored; admin page without the admin password shows only the login form; CSV refused without it; wrong admin password refused; the site access password does not open it; the right one does; the page shows by-day totals, 👍/👎 and the 👎 list; the CSV downloads with a header and quoted fields (UTF-8 with a byte-order mark, so Excel opens it). Draft and review votes saved with their snapshots; upload, review and draft counters each went up by one per action.

**Keyboard and 375 px.** Feedback bar: Space toggles a quick pick, Tab runs picks, comment, Send, Not now; 👎 stays pressed after a reload. Scan labels, the Schedule cards, the Vault list and the admin page all show no sideways page scroll at 375 px (the admin by-day table scrolls inside its own box). Schedule table: cards on phones, a keyboard-focusable scroll box on desktop.
